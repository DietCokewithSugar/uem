# 灵犀旅程

标记说明：**【确认】**来自「灵犀旅程优化情况」说明和后续讨论；**【待定】**是步骤边界还没写死的点。

## 1. 定位【确认】

灵犀旅程方法于 2024 年建立，并已有可用的线上工具。

后续要做的四件事：

1. 把灵犀用户声音分析智能体和灵犀旅程联通。
2. 完善灵犀旅程的建立步骤。
3. 推进典型问题向优化建议转化的闭环。人工点一次生成一条待分拣建议，规则见《用户声音分析智能体》第 4、5 节。
4. 建立便于日常维护、查看的看板。

## 2. 四步【确认】

优化后的步骤分成四段：

1. 填写旅程基本信息，并审核旅程基本信息。
2. 编辑旅程结构，并审核旅程结构。
3. 编辑旅程内容。
4. 日常查看、维护旅程内容。这一步在旅程看板上做。

【待定】

1. 两段审核分别由谁做，退回后回到填写人还是编辑人。
2. 「编辑旅程内容」要不要再单独审核。说明里这一步没有并列的审核框，基本信息和结构有。
3. 第四步的「卡维护」是看板中按卡片维护，还是「查看并维护」的连写。用途已经确认是旅程看板。

## 3. 结构和内容【确认】

旅程结构只包含两样：

- 旅程行为
- 触点

驱动因素、体验指标、典型问题、优化点都挂在对应的旅程行为上，不另算一种结构。

旅程看板就是维护旅程内容的地方。声音分析里的 M4 要调取的「旅程结构」，指这里的行为和触点。

【待定】你原文写的是「其他的都是旅程行为」。本文按后一句「旅程看板就是维护旅程内容的」理解：行为与触点之外、又按行为分列的那些块，属于旅程内容。若「其他的都是旅程行为」是指它们仍叫结构的一部分，请纠正。

## 4. 和声音分析的衔接【确认】

声音已经有产品、功能，并且该功能有旅程行为时，流水线调取旅程结构，进入旅程行为分类（M4），得到 D5。没有旅程行为时，不进入 M4，改为汇总定位数据 D9。详见《用户声音分析智能体》第 3.1 节。

典型问题列表 D10 按产品 / 功能 / 旅程分组。分组用到的旅程，来自这套旅程结构。

## 5. 和演示版的差别

演示版现在是一次提交、一次审核：待编辑旅程结构 → 待审核 → 通过后已发布，或退回待修改。没有把「基本信息审核」和「结构审核」分成两个待办。

编辑页里，旅程结构一节已经是行为和触点。驱动因素、体验指标、典型问题、优化点也按行为分列，和「挂在旅程行为上」一致。这些块目前和结构在同一次编辑、同一次提交里，没有按第 2 节拆开。

旅程看板可以查看已发布旅程，并导出典型问题。它还不是第 2 节第 4 步那样的日常维护入口。
